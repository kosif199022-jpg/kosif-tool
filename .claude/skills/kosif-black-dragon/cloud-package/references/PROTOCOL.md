# بروتوكول التنين الأسود لأي فيديو (موحّد)

ده البروتوكول اللي اتبنى في المشروع واتجرب على فيديو المناظرة وأفلام ميار وريل القهوة. هو دمج لحاجتين: **بروتوكول المونتاج** (8 محطات، والشكل التقريبي قبل الرندر) و**بروتوكول الفيديو الإلزامي v2** (7 مراحل بالترتيب، وقاعدة اللون العاشر). الأصل الكامل موجود في `VIDEO_PROTOCOL_V2_ORIGINAL.md` و`PASTE_PROMPT.md`.

## القاعدة الذهبية
أي فيديو (ريل، إعلان، برومو، مونتاج، موشن، فيلم، انترو، شورتس) بيمشي في نفس المسار بنفس الترتيب. مفيش مرحلة تتخطى، ومفيش أداة تتقال إنها «اتستخدمت» من غير ما تشتغل فعلًا. **مفيش رندر نهائي قبل ما المستخدم يقول «موافق»**، إلا لو قال «نفّذ مباشرة».

## المراحل

| # | المرحلة | بتعمل إيه | الأوامر (`D` = `python3 <skill>/scripts/dragon.py`) |
|---|---|---|---|
| 0 | المكان | اعرف إنت فين: سحابة ولا جهاز | `D where` ثم `D setup` (أو `--full` لو محتاج توقيت كلام) |
| 1 | العين الأولى | حلّل المادة فعلًا: اللقطات وجودتها، الكلام بتوقيته، السكتات، الإيقاع، الوشوش، علو الصوت، الألوان. ماتقولش إنك شفت حاجة ماقدرتش تفتحها | `D verify clip.mp4`، `D run dragon_montage station analyze …`، `D words`، `D beats` |
| 2 | بطاقة الطلب | المنصة والمقاس والمدة والإحساس والجمهور والرسالة والبطل، وإيه اللي لازم يفضل وإيه الممنوع | اكتب `brief.json` |
| 3 | الفكرة | 3 أفكار مختلفة فعلًا (قصة أو إيقاع مختلف)، كل واحدة بهوك. اختار بمصفوفة قرار وقول إيه اللي يقلب القرار. **الهوك لازم ميطلعش WEAK** | `D run reel_hooks hook --hook "…"`، `D run matrices ideate`، `D find "<الفكرة>"` |
| 4 | الذوق واللون | ستايل ولون وانتقالات وحركة كاميرا وكابشن مناسبين للفكرة. لون أساسي 60٪ + مساعد 30٪ + **لون تمييز واحد ~10٪ على البطل بس** (`COLOR_TENTH.md`) | `D run dragon_montage station taste …`، `D tool motion match "…"` |
| 5 | المونتاج (EDL) | قائمة قطعات، كل قطعة ليها سبب مكتوب | `D run dragon_montage plan …` |
| 6 | **الشكل التقريبي (إجباري)** | ابعت: ستوري بورد (كادر من كل قطعة بالمقاس النهائي + شريط زمني) و**مصفوفة التحركات** (الوقت، جاية منين، الدور، حركة الكاميرا، الانتقال، الكلام، السبب) والفكرة والبدائل. **واستنى «موافق»** | مثال: `EXAMPLE_MOVEMENT_MATRIX.md` و`example-storyboard.jpg` |
| 7 | التنفيذ | 1080×1920، 30 fps، H.264 CRF 17 preset slow، BT.709 كامل، faststart، صوت −14 LUFS، كابشن عربي في المنطقة الآمنة | `D film spec.json`، `D run dragon_montage go …`، `D run talking_head render …`، `D run web_film render …` |
| 8 | يتفرج وينقد | اتفرج على النسخة فعلًا (كادرات من جوه الفيديو)، اكتب المشاكل وصلّح لحد 3 جولات، واحتفظ بأحسن جولة | `D verify out.mp4 --expect 1080x1920 --out evidence.json` |
| 9 | التسليم | افصل بين اللي **اتشغّل فعلًا** على مادة المستخدم واللي **اتقرا بس كمرجع**، وقول إيه الأدوات اللي كانت ناقصة | تقرير زي `EXAMPLE_DEBATE_REPORT.md` |

## بوابات لا تتكسر
- **الهوك:** لو `reel_hooks` قال WEAK، اكتب هوك أقوى قبل ما تكمل (في تجربة القهوة الهوك الأول أخد 30/100 واترفض، والتاني أخد 80).
- **اللون:** في التصميم فرق اللون (ΔE) بين التمييزي والخلفية ≥ 40. في الفحص لون التمييز بين 0.5٪ و18٪ من الكادر.
- **الصورة لازم تملا الكادر:** مفيش حواف فاضية في 9:16. الصورة الأفقية تتحط cover أو فوق خلفية مموهة منها.
- **التحقق:** مفيش «خلص» قبل `verify` على الملف النهائي نفسه.
- **الفلوس والنشر:** مفيش صرف كريدت (Kling، Higgsfield، Suno) ولا نشر ولا رفع غير بعد ما تعرض الاقتراح والسعر والمستخدم يقول «أيوه».
- **الملفات الأصلية:** ماتتعدلش أبدًا. اشتغل على نسخة.

## الحلبة (بعد التسليم لو الإجابة اترفضت)
لو المستخدم قال «الإجابة وحشة» أو «خليهم يتنافسوا» أو «الحلبة»: نفس المهمة بالحرف تروح لـ 16 وكيل (100 لو طلبهم بالاسم)، كل واحد بكارت تفكير مختلف، يهاجموا حلول بعض، والحَكَم يقيّم على `tools/arena/rubric.md`، وفي الآخر مقارنة عمياء مع الإجابة المرفوضة. الأداة: `D tool arena plan|init|next|…`، والشرح الكامل `ARENA.md`. المنسّق ماييحكمش بنفسه.
