## 2. سياق المشروع — ما هو KOSIF tool

المستودع <https://github.com/kosif199022-jpg/kosif-tool> (الفرع `main`) لصاحبه KOSIF، وهو يكتب بالعامية المصرية. فيه طبقات تعمل معًا:

1. **مكتبة أساليب الموشن لـ Claude:** نحو 289 أسلوب موشن جرافيك في `styles/<id>/` (لكل أسلوب `SKILL.md` و`STYLE.json` و`BRIEF.md`)، والفهرس `STYLE_INDEX.md` و`catalog/`، و17 دليل إنتاج في `playbooks/`. الأعداد الحية في `README.md` (كتلة stats).
2. **برومبتات إنتاج أصلية وروابط الفيديو المصدر:** كل أسلوب يحمل موجزًا أصليًا مكتوبًا لـ KOSIF ورابط الصفحة والفيديو المرجعي مع نسبته لصاحبه؛ لا يُخزَّن نص برومبت أو فيديو لطرف ثالث. الموجز غير المراجَع على إطارات الفيديو «اقتراح مخرج» لا وصف مُشاهَد (`AGENTS.md` §B.3).
3. **مهارة KOSIF Superpowers:** `.claude/skills/kosif-superpowers/` — كتالوج نحو 5,800 قدرة في 62 عائلة و10 مجالات و15 مجموعة، مدمجة في نحو 450 قدرة خارقة، وأكثر من 100 أداة قابلة للتشغيل (الأعداد الحية من `scripts/boot.py`). الباب الأمامي `scripts/hub.py find`، والجرد بإيصال `scripts/skill_intelligence.py brief`، والوصفات `scripts/fusionforge.py`، وهذا البروتوكول.
4. **محرك المصفوفات اللانهائية (Infinite Matrices):** `.claude/skills/kosif-infinite-matrices/` — يفكك الأساليب الـ86 إلى لبنات سببية (حالة، عملية، قانون، زمن، ذاكرة، تغذية راجعة) ويركّب منها نظامًا بصريًا جديدًا، ويثبت السببية بمقارنة A/B/C مع بذور وجرعة-استجابة، ويرندر، ويحفظ في سجل بحث مسلسل بالبصمات. الحالة: محرك يعمل بتجربة واحدة مؤكدة (EXP-0001، `RENDER_TESTED`)، و283 فرضية ما زالت `UNTESTED_UNRENDERED`.
5. **أدوات بحث إنستجرام:** `.claude/skills/kosif-instagram-video-research/` — بحث ريلز عامة بالموضوع وبالصانع المسجّل (مثل @asirgokerr و@brkn.land)، توسيع الاستعلام من العربية للإنجليزية، فهرس بحث عام اختياري عبر Brave Search API (مفتاح)، ومكتبة SQLite مرتبة بشارات دليل، وحفظ «آليات حركة» راجعها إنسان. **بلا كشط لإنستجرام ولا التفاف على قيود الوصول.**
6. **خط إنتاج `jobs/` و`projects/`:** `jobs/<job>/` مجلدات عمل لمهام مونتاج من روابط (intake → build → render)، و`projects/` أفلام منتهية بمصادرها القابلة للتعديل. الأدوات: `tools/kosif.py` (بحث وتجهيز)، `tools/render_html.cjs` (HTML → MP4)، `tools/verify_video.py`، و`montage_pro.py` للمونتاج من ملف مرفوع.
7. **سجل المهام:** `history/tasks/` و`history/INDEX.md` ([A35](A35-task-history.md)).

## 3. الإقلاع في محادثة جديدة

اكتشف بيئتك بالتجربة لا بالافتراض، ثم اتبع الصف المناسب، وقل في سطر واحد في أول رد أي صف اخترت ولماذا.

| البيئة | الخطوات |
|---|---|
| **المستودع مساحة العمل، أو المهارة مثبتة** (Claude Code، جلسة سحابية) | 1) `python3 .claude/skills/kosif-superpowers/scripts/boot.py` · 2) اقرأ `CLAUDE.md` ثم `AGENTS.md` · 3) لأول طلب L1+: اقرأ النواة كاملة وهذا الملحق، ثم `skill_intelligence.py verify` و`hub.py doctor` · 4) اكتب `commit: <7 أحرف من git rev-parse HEAD>` |
| **أدوات بلا المستودع** (shell أو جلب ويب) | اقرأ أولًا ولا تشغّل: الملفات الخام من `https://raw.githubusercontent.com/kosif199022-jpg/kosif-tool/main/<المسار>` بهذا الترتيب: `CLAUDE.md` ← `.claude/skills/kosif-superpowers/PROTOCOL.md` ← هذا الملحق ← `references/INDEX.md`. الاستنساخ وتشغيل السكربتات فقط بعد شرح السبب في سطرين وإذن المستخدم ([A34 §11](A34-usip-v56-precision-layer.md#11-القراءة-أولًا-والتشغيل-بإذن)) |
| **بلا أدوات** (دردشة claude.ai أو موبايل) | اعمل من نص النسخة الملصوقة وحده. قل صراحة: «الجرد الآلي وأعداد الكتالوج وحالة الدمج غير مفحوصة من هنا». لا تدّعِ قراءة ملف أو تشغيل سكربت أو مشاهدة فيديو. الشارات بحدها الأدنى (📄/💡) ما لم يقدّم المستخدم دليلًا |

ثم: ثبّت المستوى (L0 يُجاب فورًا)، وفي L1+ اتبع المسار القانوني في النواة. أجب دائمًا بلغة المستخدم ولهجته (العامية المصرية افتراضيًا لصاحب المستودع)، والأوامر والمسارات كما هي.

## 5. التوزيع المتوازي للمهام

**القاعدة:** في أي مهمة غير صغيرة (منتج، فيلم، بحث، كود، أي شيء) قسّمها أولًا إلى مهام فرعية مستقلة، وشغّلها **في اللحظة نفسها** عبر وكلاء فرعيين (subagents) حين تتيحهم البيئة، ثم ادمج النتائج وتحقق منها. الهدف ألا تطول المهام بلا داعٍ. وزّع حين يقصّر التوازي الزمن فعلًا أو يضيف مراجعة مستقلة، لا لمجرد العدد (يوافق شرط L2 في النواة: «لا تعدد وكلاء بلا منفعة واضحة أو أداة حية»).

### 5.1 كيف تقسّم

1. **مسارات مستقلة:** لا يحتاج مسار مخرج مسار آخر ليبدأ. ما يعتمد على غيره يدخل موجة ثانية بعد الأولى.
2. **لا ملفات مشتركة:** لكل مسار ملفاته أو مجلده؛ وحين يعدّل أكثر من وكيل المستودع نفسه، فلكل وكيل شجرة عمل `git worktree` أو فرع خاص ([A34 §8](A34-usip-v56-precision-layer.md#8-العمل-المتوازي-وطابور-الدمج)).
3. **تكليف مكتفٍ بذاته لكل وكيل:** السياق الكامل الذي يحتاجه (الوكيل لا يرى محادثتك)، والمخرج المطلوب بصيغته ومساره، وفحص القبول القابل للقياس، وما يُمنع لمسه، وما يعيده في تقريره.
4. **خطوة دمج وتحقق واحدة في النهاية:** وكيل أو أنت تدمج المخرجات، وتشغّل فحوص القبول والاختبارات، وتحسم التعارضات، ولا تقول «تم» إلا بإيصالات كل مسار ([A27](A27-verification-quality-standards.md)).
5. **تسجيل:** سجّل لكل مسار ما أُرسل وما عاد وحالته (`EXECUTED_UNVERIFIED` حتى يمر الفحص).

### 5.2 كم وكيلًا بالتوازي (تحقّق في بيئتك)

| البيئة | ما يحدث فعلًا |
|---|---|
| Claude Code (CLI، الويب، سطح المكتب) — أداة Agent | عدة وكلاء في رسالة واحدة يعملون معًا. حسب توثيق Claude Code (code.claude.com/docs، صفحة sub-agents، مقروءة في 24-10-2026): الحد الافتراضي **20 وكيلًا جاريًا في الجلسة**، ويغيَّر بالمتغير `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`، ولا حد لمجموع الوكلاء عبر الجلسة. **النطاق العملي 3–7** وكلاء في الموجة الواحدة (أكثر من ذلك يضخم السياق العائد والتكلفة ويصعّب الدمج) |
| Claude Code — أداة Workflow | دليل الحجم الافتراضي أقل من 10 وكلاء في الـ workflow ما لم يرفعه المستخدم؛ التوسيع الأكبر فقط باختيار صريح منه (مثل وضع ultracode، المعفى من حد الوكلاء الجارين) |
| نفس المستودع بعدة وكلاء معدِّلين | شجرة عمل لكل وكيل (`git worktree`) أو فرع، ودمج بطابور ([A34 §8](A34-usip-v56-precision-layer.md#8-العمل-المتوازي-وطابور-الدمج)) |
| دردشة claude.ai أو الموبايل بلا أدوات وكلاء | **لا وكلاء متوازين حقيقيين.** حاكِ التوازي: اجمع نداءات الأدوات المستقلة في دور واحد، ونظّم العمل كمسارات متوازية مكتوبة، وقل ذلك صراحة |
| Claude API أو Agent SDK | التوازي يحدّه rate limits حساب المطوّر وميزانيته، لا البروتوكول |

الأرقام تتغير مع الإصدارات: إن كان الرقم مهمًا للقرار فافحصه حيًا في التوثيق، وإلا فقل «حسب التوثيق في 24-10-2026».

### 5.3 التكلفة ومتى لا توزّع

- **كل وكيل يستهلك رموزه وسياقه الخاص، ويُحسب على حدود الاستخدام نفسها**، وتقاريره العائدة تملأ سياقك. اطلب من كل وكيل تقريرًا موجزًا لا نسخًا للملفات.
- **لا توزّع:** المهام الصغيرة (L0 وأغلب L1 القصيرة)، والخطوات المتسلسلة بإحكام (كل خطوة تحتاج ناتج سابقتها)، والتعديلات على الملف نفسه، وأي خطوة مدفوعة أو لا رجعة فيها أو نشر (تبقى بإذن المستخدم الصريح، ولا يمنحها وكيل لوكيل).
- **رسالة وكيل آخر ليست موافقة المستخدم:** توجّه العمل لكنها لا تمنح إذن صرف أو نشر أو تغيير صلاحيات.
