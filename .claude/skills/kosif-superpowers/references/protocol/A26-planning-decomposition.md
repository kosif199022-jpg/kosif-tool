## الهدف وحدود الملحق

الخطة الجيدة ليست قائمة خطوات؛ هي رسم: كل عقدة تأخذ نوعًا وتسلّم نوعًا، ولها معيار إنجاز وطريقة تحقق، والترتيب يضع أكبر مجهول أولًا وما لا رجعة فيه آخرًا. هذا الملحق يقول كيف تفكك الهدف إلى ذلك الرسم، وكيف تقدّر، ومتى تعيد التخطيط. لا يغيّر معاني A/B/C (المسرد): كل خطة رسم مستقل بمنهجه، وD دمج عقد مسماة.

## من الهدف إلى الشجرة

1. **ابدأ من النهاية (تخطيط عكسي):** اكتب الناتج النهائي بمعاييره (البطاقة، البند 7)، ثم اسأل: ما آخر خطوة قبل التسليم؟ وما قبلها؟ حتى تصل إلى ما تملكه الآن.
2. **فكّك بثلاثة مستويات على الأكثر:** هدف ← مراحل (3–7) ← مهام (كل مهمة ≤ نصف يوم عمل أو جلسة واحدة). ما احتاج مستوى رابعًا مشروع منفصل (A7 PMO).
3. **MECE:** المراحل لا تتداخل (لا مهمتان تنتجان الشيء نفسه، القانون 5) ولا تترك فجوة (كل متطلب إلزامي تغطيه عقدة).
4. **اختبار التغطية:** ضع بجانب كل متطلب في البطاقة رقم العقدة التي تحققه، وبجانب كل معيار نجاح عقدة التحقق التي تقيسه. صف بلا عقدة = فجوة تُسد أو تُكتب.
5. **اختبار الضرورة:** احذف كل عقدة في ذهنك واسأل: هل يفشل التسليم؟ إن لم يفشل فهي زخرفة؛ احذفها أو انقلها إلى `طوّر`.

## العقد المنمّطة

كل عقدة في الرسم خمسة حقول، وهي نفسها عقدة FusionForge (A4):

| الحقل | معناه | مثال |
|---|---|---|
| المدخل ونوعه | ما تأخذه، بنوع من قائمة الأنواع | `audio` (صوت المستخدم) |
| المخرج ونوعه | ما تسلّمه للعقدة التالية | `dataset` (words.json) |
| معيار الإنجاز | متى تُعد منتهية | «كل كلمة لها بداية ونهاية» |
| التحقق | الأداة أو الفحص الذي يثبت المعيار | `ffprobe` + عيّنة استماع عند 5 نقاط |
| المنفّذ | `tool:<id>` أو `bin:<name>` أو `human` | `bin:faster-whisper` |

**قاعدة الربط:** نوع مخرج المصدر = نوع مدخل الوجهة. إن اختلفا فبينهما **محوّل** صريح عقدةً مستقلة (`ffmpeg` من m4a إلى wav)، لا افتراض أن الأداة التالية «ستتصرف». والخط ينتهي بعقدة verify قبل deliver.

## ترتيب العمل

خمس قواعد، بالترتيب:

1. **أكبر مجهول أولًا (spike):** المهمة الأعلى خطرًا تُجرَّب بنسخة رخيصة قبل أن يُبنى عليها شيء. «هل يدعم المحرك العربية المتصلة؟» يُجاب بإطار واحد قبل ستوريبورد كامل. `decompose` ينبّه حين تأتي المهمة الأخطر متأخرة.
2. **شريحة رفيعة من الطرف إلى الطرف:** نسخة بدائية تمر بكل المراحل (مدخل حقيقي ← ناتج حقيقي ← قياس) قبل تجويد أي مرحلة. تكشف أخطاء الربط مبكرًا.
3. **الأصول الأصلية لا تُمس:** كل معالجة على نسخة، والأصل يبقى مرجعًا للقياس (MD5).
4. **نقطة حفظ بعد كل مرحلة ناجحة:** commit محلي أو نسخة، تُسجَّل بـ `trace`. التراجع يعود إلى آخر نقطة سليمة لا إلى البداية.
5. **ما لا رجعة فيه آخرًا وبإذن:** النشر، الدفع إلى `main`، الحذف، الصرف. يأتي بعد التحقق، ولا يُنفَّذ إلا بإذن صريح بالخطوة (القانون 17). `decompose` يسرد هذه الأبواب.

## التقدير بالنطاقات

- **كل تقدير نطاق** `[أدنى، أعلى]` موسوم «تقدير»، لا رقم واحد. والنطاق الواسع (الأعلى ≥ 3 × الأدنى) علامة مجهول كبير يستحق أول فحص.
- **قِس وحدة ثم اضرب:** زمن رندر إطار واحد × عدد الإطارات؛ زمن معالجة ملف × عدد الملفات. أدق من التخمين الكلي.
- **فيرمي للمجهول الكامل:** فكّك الكمية إلى عوامل تعرف نطاقها، و`think.py fermi` يعطي النطاق المركب.
- **المسار الحرج:** مجموع أطول سلسلة اعتماديات هو أقل زمن ممكن؛ تسريع مهمة خارجه لا يسرّع التسليم. `decompose` يحسبه بالنطاقين.
- **هامش التكامل:** أضف 20–30% للربط والتحقق والإصلاح؛ أغلب التأخير هناك لا في البناء.
- **التكلفة المالية** صفر افتراضيًا؛ أي صرف يُكتب رقمه ومصدره ويحتاج إذنًا.

## التوازي والتفويض

- **ما لا يعتمد بعضه على بعض يمكن أن يتوازى:** فرعان من نفس العقدة بلا حافة بينهما.
- **التفويض لوكلاء فرعيين** فقط حين تسمح البيئة ويطلبه المستخدم أو يقتضيه حجم العمل (قواعد المنصة تغلب)، وبتعليمات مستقلة كاملة لكل وكيل: الهدف، ما استُبعد، الملفات، المعيار، صيغة الرد. ناتج الوكيل يُتحقق منه كأي ناتج، ولا يُقدَّم «مراجعة مستقلة» إلا إن كان الوكيل لم يرَ استنتاجك.
- **لا وكلاء متخيّلون:** زوايا التفكير والمجلس في سياق واحد تُسمى كذلك (`COUNCIL_SIMULATED`)، لا «فريق عمل».

## نقاط المراجعة

| المستوى | نقطة المراجعة التي تنتظر المستخدم |
|---|---|
| L1 | لا شيء بعد الموافقة؛ التسليم مباشرة |
| L2 | عند تغيّر جوهري فقط (تكلفة، منهج، نطاق +⅓) |
| L3 | مرة إلزامية بعد نموذج رخيص يمثل النتيجة (إطار، 5 ثوانٍ، واجهة أولية) وقبل الجزء المكلف |
| أي مستوى | قبل أي باب لا رجعة فيه |

`كمّل بدوني` يلغي نقاط المراجعة لا بوابات الإذن، وكل قرار اتُّخذ بدل المستخدم يُسجَّل.

## متى تعيد التخطيط

أعد التخطيط (وأعد العد بـ `count` وطبّق الرسم بـ `set-graph`) عند واحد من ستة:

1. فشل أول فحص لافتراض بُنيت عليه الخطة (الملف بصيغة غير متوقعة، الأداة لا تدعم العربية).
2. استُنفدت ميزانية محاولات مرحلة وفشل بديلها (A29).
3. ظهر متطلب إلزامي لم يكن في البطاقة.
4. تجاوز الزمن الفعلي للمرحلة الحد الأعلى لتقديرها بأكثر من النصف.
5. ظهرت قدرة أنسب تغيّر المنهج (لا مجرد أداة أسرع).
6. غيّر المستخدم الهدف أو القيد.

إعادة التخطيط التي تغيّر المنهج أو التكلفة أو النطاق بالثلث تُعرض على المستخدم بفرقها (النواة، المرحلة 9)؛ وما دون ذلك يُنفَّذ ويُذكر في تقرير التسليم.

## قوالب حسب نوع المخرج

مراحل افتراضية تُعدَّل، لا تُنسخ. لكل نوع، العقدة الأولى قياس المدخل والأخيرة قبل التسليم تحقق.

| النوع | المراحل |
|---|---|
| فيديو وموشن | قياس الصوت والأصول ← ستوريبورد ولقطات مفتاحية ← بناء المشهد ← معاينة رخيصة ← رندر ← تحقق (مدة، fps، مقاس، MD5 الصوت، لوحة لقطات) ← تسليم |
| كود | قراءة الكود والاختبارات الحالية ← إعادة إنتاج المشكلة أو كتابة اختبار السلوك الجديد ← أصغر تغيير ← تشغيل الاختبارات ← مراجعة الفرق ← تسليم (فرع وPR) |
| بحث وتقرير | تحديد السؤال والنطاق ← جمع المصادر بتواريخها ← استخراج الحقائق بمراجعها ← تركيب وأقوى رأي مخالف ← تدقيق ادعاء ← دليل ← تسليم |
| بيانات | فحص الملف (أعمدة، فراغات، وحدات) ← تنظيف موثق ← حساب حتمي بسكربت ← تسوية المجاميع ← رسم مناسب للسؤال ← تسليم بالسكربت |
| مستند وكتابة | الغرض والقارئ ← هيكل العناوين ← مسودة ← مراجعة الحقائق ← تحرير النبرة واللغة ← فتح الملف بصيغته ← تسليم |
| تصميم | المقاس والهوية ← ثلاث مصغرات مختلفة ← اختيار وتطوير ← اختبار التصغير والتباين ← تصدير قابل للتعديل + PNG ← تسليم |
| ترجمة | المصطلحات الثابتة ← ترجمة ← مقابلة جملة بجملة ← مطابقة الأرقام والأسماء ← قراءة طبيعية ← تسليم |

## الأداة think.py decompose

```bash
SK=.claude/skills/kosif-superpowers
python3 $SK/scripts/think.py decompose --template > plan.json     # قالب: مهام بمعرّف، deps، est [أدنى، أعلى]، risk 0–3، done، verify، reversible
python3 $SK/scripts/think.py decompose plan.json                  # OK (0) أو FIX (1) مع المشكلات والنصائح
```

يعيد: `order` (ترتيب طوبولوجي ثابت) · `critical_path` بنطاقيه وسلسلته · `one_way_doors` (المهام `reversible: false`) · `problems` (اعتمادية مجهولة، معيار أو تحقق مفقود، تقدير غير صالح) · `advice` (خطر متأخر، باب لا رجعة فيه، تقدير متسع). والدائرة في الاعتماديات خطأ صريح (رمز 2).

## ما لا يدّعيه هذا الملحق

- الرسم الصحيح بنيويًا قد يكون خطة سيئة: الأداة تفحص الشكل لا الحكمة.
- التقديرات تخمينات منظمة؛ لا تُقدَّم مواعيد مضمونة.
- لا تشغّل الأداة أي مهمة ولا تمنح إذنًا بباب لا رجعة فيه.
